# MOS 6510 and MOS 8500 — local static analysis

Select `--architecture 6510` or `--architecture 8500`. The architectures are
explicit raw-only CPU choices, never inferred from the file name or header.
Both accept byte-aligned mappings within the 16-bit address space.

| CPU option | Ghidra language | Compiler | Default space |
| --- | --- | --- | --- |
| `6510` | `6510:LE:16:default` | `default` | `RAM` |
| `8500` | `8500:LE:16:default` | `default` | `RAM` |

The REA6510 data-only module inherits the documented 6502 instruction model
from Ghidra 12.1.4. It uses separate language IDs and processor specifications
for the two CPUs, not the 65C02 language. Files and Apache-2.0 license are in
`third_party/retro-processors/REA6510`.

## On-chip port

Both processor specifications name the byte at $0000 `CPU_PORT_DDR` and the byte
at $0001 `CPU_PORT_DATA`, marking them volatile. This prevents the decompiler
from treating external input reads as ordinary constant RAM contents. The raw
analysis profile records the port-model version and preserves which CPU was
selected. CPU identity remains distinct from 6502 in CLI and MCP Evidence.

The Commodore 64 Programmer's Reference Guide describes the port's bit-level
memory/cassette connections. These system-specific effects are not emulated.
External inputs, pull-ups, unused bits, electrical characteristics, undocumented
opcodes, cycle timing, BASIC/KERNAL/character ROM mapping and VIC-II/SID/CIA
behavior require an explicit machine model or emulator. This addition does not
infer a C64 bank configuration from a write to $0001.

## Install/use

The new module is already installed in this computer's local Ghidra. To restore
it elsewhere, explicitly run the existing offline installer with your paths:

```powershell
python scripts/install-local-retro-processors.py --ghidra C:\tools\ghidra_12.1.4_PUBLIC --java-home C:\tools\jdk-25
npm run build:cached
```

Configure GHIDRA_INSTALL_DIR and JAVA_HOME for your own installation. Example:

```powershell
node scripts/rea.mjs function program.raw 0x1001 --target-format raw-binary --architecture 6510 --entry-point 0x1001 --provider ghidra --json
node scripts/rea.mjs function program.raw 0x1001 --target-format raw-binary --architecture 8500 --entry-point 0x1001 --provider ghidra --json
```

The raw contract maps file offset zero at entry-point. A separate execution
entry requires the existing REA_GHIDRA_SEED_FILE setting. C64 PRG/tape/disk
containers are not imported automatically: extract the payload and preserve
its actual load address before analysis.

The regression verifier has self-owned fixtures for both CPUs. It checks the
selected language, original bytes, initialized file mapping, instruction output,
port symbol names in pseudocode and that a port read is not folded to the value
last stored. Run with existing Ghidra/JDK environment settings:

```powershell
node scripts/verify-local-retro-cpus.mjs C:\analysis\6510-proof 6510,8500
```
